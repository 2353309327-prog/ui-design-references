# UI 设计参考

本 skill 是跨项目的 UI 设计偏好。用户给出的品牌规范、设计稿、功能要求和项目现有设计系统优先；在其允许的空间内，用以下资源提升视觉质量。普通功能修复或不涉及视觉的代码任务无需套用。

## 参考资源

| 用途 | 资源 | 使用方式 |
| --- | --- | --- |
| 风格探索与提示词 | [DesignPrompts / StyleKit](https://designprompts.dev/) | 按产品类型和页面目标挑选合适的风格、页面结构或提示词，提炼字体、色彩、布局、间距、图像和交互规则。站内内容与数量可能变化。 |
| 网站审美 | [Godly](https://godly.website/)（现转向 [Recent](https://recent.design/websites)） | 参考高质量网站的视觉方向、构图和动效。 |
| UI 审美 | [Dribbble](https://dribbble.com/) | 参考界面细节、组件、排版和视觉表达；注意作品图未必展示完整可用流程。 |
| 落地页 | [Landingfolio](https://www.landingfolio.com/) | 参考首屏、信息层级、内容区块和转化路径。 |
| 代码与组件实现 | [v0](https://v0.app/) | 参考实现方式、组件拆分与交互思路；以当前项目的技术栈和约定实现。 |
| 图标 | [Lucide](https://lucide.dev/) | 在没有既定图标系统时优先选用语义准确、风格一致的图标，保持尺寸和描边统一。 |

## 工作方式

1. 明确页面的用户、目标、内容与现有品牌约束。根据页面类型挑选相关参考；有网络访问且任务需要新视觉方向时查看当前页面，避免依赖过时截图或固定风格数量。
2. 先形成简短的视觉方向：主要风格、字体层级、色彩、栅格与留白、关键组件、图像和动效。让参考服务于内容和产品定位，不拼接互不相容的流行效果。
3. 实现时遵循项目已有框架、组件库、设计 token 和响应式断点。参考 v0 的代码思路即可，不要求迁移到其默认技术栈。
4. 完成后检查桌面与移动布局、可读性、对比度、键盘操作、交互状态、图标一致性和真实内容长度。若能预览，按实际渲染效果调整细节。

参考站点用于启发与分析。不要直接复制受保护的页面、图片、文案或付费组件；需要外部资源时确认其许可与可用性。
